APP EXPERIENCE AND ACCEPTED BEHAVIOR
Updated: 2026-11-15
Scope: intended/accepted original-app behavior. This is not an exhaustive fresh code audit. Latest phone outcomes are in 04-remaining-work.txt.

LOOK AND FEEL
Warm Harvest Kitchen palette; muted pastel weekday cards; neutral surfaces; rounded corners; soft shadows; readable dark text.
Compact spacing, predictable icon columns, naturally wrapped names, comfortable touch targets. Avoid icon-induced blank rows, overlapping text, excessive padding, solid triangle disclosure icons, or gray boxes around every editor section.
Small blue checkboxes; radio dots for exclusive choices; consistent outline chevrons and check/trash/X icons.
Dialogs scroll in foreground, lock background, and keep actions usable with keyboard/landscape. Preserve accessible keyboard focus.

NAVIGATION AND PLANS
Main views: My Rotation, Weekly Overview, Groceries, Meal Groups. Compact bottom-right navigation.
Separate renameable/reorderable meal tabs, e.g. Breakfast/Lunch/Dinner.
Show meal tabs hides/reveals tabs without deleting plans; visible plus adds a plan even with one existing tab. No Add Meal Tab Settings button.
Current week and generated next-week preview are distinct. General editing of generated future schedules has not been approved.
Ordinary page changes go top; targeted navigation finds exact occurrence.
Aggregate-page tab policy remains a status/design-confirmation item; do not invent scope.

ROTATION
Assign groups to weekdays; configurable weekday order; multiple groups/day; empty days allowed.
Select outside the assigned group through searchable group/recipe picker.
Rotate Meals controls advance selected occurrences according to group order; preserve other plans/weeks/manual choices.
Short tap opens recipe; long-press options. A popup action dispatches once, responds promptly, and prevents tap-through.
Last cooked: actual cooked date recorded for outgoing occurrence, otherwise scheduled local date, never simply button-press date.
Scaling is ALREADY implemented: occurrence multiplier 1/2x, 1x, 1 1/2x, 2x, 3x; original recipe unchanged, groceries proportional.

MEAL OPTIONS
Header recipe name, Favorite heart, X; compact Last cooked date/pencil beneath.
Standard rounded outlined buttons: Change meal; Add or edit sides; Edit recipe; Edit groceries.
No redundant Open recipe, separate rotate, or separate skip action here.
Change meal picker shows:
1. Use next recipe.
2. Leave Tuesday empty (tabs hidden), or Leave Tuesday's dinner empty (tabs shown); actual names.
3. Choose a different meal with search/groups already displayed.
Empty means only selected occurrence, not other dishes on the day.
Skipped dash retains long-press access; no duplicate Auto-Populate action.

DUPLICATE MEAL
Heading: "[Recipe] is already planned for [weekday]."
Radio choices: "Use a different meal on [weekday]" / "Keep [Recipe] on [weekday] too"; check/X, no subtext.
First automatically replaces source using normal eligible selection; second keeps both. Destination/source update safely together; cancel leaves no partial change. Empty destinations and Ideas choices must work. No eligible replacement should not silently corrupt either day.

GROUPS AND IDEAS
Two statuses: In Rotation and Ideas, NOT three.
In Rotation eligible for automatic rotation; Ideas manually schedulable without promotion.
Ideas pins: outlined/filled, left column; pinned first. Pin/unpin brings first in corresponding portion. Long-press drag within each portion, shared persistent order across memberships, hidden relative order preserved.
In Rotation down arrow directly moves to Ideas, pins first; Ideas up arrow directly promotes to top of In Rotation. No status popup from arrows or visible reorder arrows.
Hearts are Favorites, separate from priority pins; preserve underlying values and adjustment notes.
Many group memberships represent one logical recipe; no multi-group chain clutter.
Group create/rename/reorder/collapse/search. Unassigned when no named memberships.
Use for meal rotation off = plain reference list, no new rotation assignments; statuses preserved. Existing assignments must be removed before disabling, with explanation; no destructive automatic changes.
Add meals button, "Add meals to [group]" picker; standard chevrons; Copy keeps original membership, Move removes it; no "Add meals by:" heading.
Search multi-word AND; optional Match word order off by default.

BULK EDIT
First selection establishes source group; restrict selection to it until Done/deselect all. Toolbar group/count; Select all respects filters.
Independent Remove from [source] and Add to groups. Preserve other memberships; destinations required for Add; no named memberships -> Unassigned. Omit Remove from Unassigned.
New groups and changes pending until outer final check; X cancels.
Status Keep existing/In Rotation/Ideas, mixed values preserved by Keep existing.
No bulk Favorite/Needs Adjusting or redundant Move toolbar.
Picker heading/actions/footer fixed, destination list scrolls, chevrons on subpicker rows.
Delete selected names with "Delete these recipes?" and note "Unselected linked recipes will not be deleted."

BUILT-IN SIDES AND PREFERENCES
App-provided Sides group has stable identity, can rename/reorder, cannot delete. Reuse existing group without duplicate migration; In Rotation/Ideas remain.
Sides assigned to day + preferred types -> matching eligible side rotation.
Sides assigned + no preferences -> normal Sides rotation.
Sides not assigned -> do not generate preferred side recipes.
Preference edit updates this week's automatically chosen side, retains already valid choice, doesn't advance repeatedly on unchanged Save.
Ask before replacing a manually chosen side. Preserve provenance across reload; unknown provenance protected.
Linked recipes/simple sides remain independent. Other groups such as Veggies unaffected.

SIMPLE SIDES
Name plus optional ingredient lines; no full recipe required; multiple sides supported. No inferred groceries.
One direct editor from meal options, existing side text rows with pencil/trash; optional ingredients collapsed with outline chevron.
New side: inline Always question, radio Always/This time only (default latter), standard check/X. Check saves/closes directly; no nested manager/confirmation chain.
Always = selected occurrence + parent defaults for future scheduling; other scheduled occurrences unchanged. This time only = selected occurrence.
Existing side edit from My Rotation occurrence-only. Recipe editor manages defaults.
Trash removes pending side; final check saves; X cancels pending removals/edits. No red confirmation/lone-check state.
Stable IDs, no duplicates, explicit empty overrides persist. Groceries scale with parent; linked recipes unaffected.
Reload persistence required; session Undo works, persistent Undo after reload not required.

GROCERIES
Heading Groceries; toolbar alongside or flush-left wrapped.
Independent This week/Next week checkboxes; included-plan choices. Combined list default.
Checked items move top; Select All/Deselect All/Hide Selected. Preserve checks when adding/editing; newly rotated-in sources unchecked without resetting others.
Manual items add/check/edit/delete, long-press edit; survive filters, week switches, reload, individual rotation.
Explicit whole-week advance clears checked manual items only; unchecked stay; Undo/Redo restores/removes. No calendar cleanup.
Recipe-generated shopping text edits do not change recipe ingredients.
Compact expanded source names clickable -> correct ingredient in internal viewer. Association survives wording/scaling. Split-view linked-step positioning incomplete/deferred.
Ambiguous combining and edited-quantity scaling remain deferred; preserve existing handling without pretending solved.

TASKS / OVERVIEW
Due dates from scheduled occurrence + lead time, can precede meal week.
Overview tasks on actual due dates; checking doesn't move date.
Overdue incomplete task may stay until associated planned day passes then hide.
Today's To-Do only kept visible by eligible incomplete due-today/overdue tasks. Hide whole card/eye/spacing when none, even Show completed. Future tasks do not keep visible.
Next Week's To-Do includes prep due before that week; hide all complete.
Compact wording "[task] for Sunday's dinner", no duplicated recipe title/"meal tab". User text preserved.
Text tap -> exact meal/plan/week; checkbox only completes; long-press edits. No heavy blue title box; subtle card shadow intended but visibility unconfirmed.
Compact task padding/alignment desired; some polish deferred.

RECIPES / COOKING
Internal recipe viewer, source URL retained.
Tap ingredient/step complete; persistent progress and manual reset without confirmation; occurrence-aware isolation/reset.
Split view narrow draggable divider; landscape ingredients left/instructions right.
Explicit ingredient-step links: highlighting, optional auto-completion, next-incomplete-step scroll, manual ingredient uncheck; optional complete previous steps.
Long-press step links ingredients inline. Viewer may reorder by use while saved ingredient order unchanged.
Linked-recipe tabs optional, main first, scroll position per tab, scroll/reorder, truncate long names, hide single-tab bar.
Edit/scale near title, consistent split/reset/settings; keep screen awake capability.
Editor substantial sections independently collapsible, no outer gray boxes; unsaved edits/links preserved.
Linked selector initially collapsed groups, reference/Unassigned included, shared selection across memberships, search expands matches, clear restores expansion, final check/X.
Android Back returns once to origin, not an extra hop.
Needs Adjusting optional note editable without autofocus; no Edit note intermediary; bottom check/trash/X, trash removes mark not recipe; no scheduling/cooked-date effects.
Labels, times, notes, source, ingredient upload/import and recipe status retained.
